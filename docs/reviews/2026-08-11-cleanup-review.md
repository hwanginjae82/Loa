# 2026-08-11 임시 코드 정리 및 리뷰

## 작업 목적

- 초기 개발용 데이터와 일회성 복구 코드를 실제 서비스 코드에서 제거한다.
- 일정 데이터 처리 로직을 화면 코드와 분리한다.
- 공용 일정 저장 과정에서 데이터가 사라질 수 있는 부분을 점검한다.

## 정리한 내용

- 초기 멤버 데이터 파일 제거
- 초안 일정 미리보기 코드와 테스트 제거
- 완료된 일정 복구·가져오기 스크립트 제거
- 완료된 복구 작업의 일회성 계획·설계 문서 제거
- 사용하지 않는 Supabase 재노출 파일 제거
- 사용하지 않는 CSS 클래스 제거
- 날짜, 주차, 일정 정규화, 캐릭터 재연결, 레이드 정렬 로직을 `src/boardModel.js`로 분리
- 현재 프로젝트 구조에 맞게 `README.md` 갱신

## 리뷰에서 발견하고 수정한 버그

### 1. 새 레이드 추가 창의 기본 색상 참조 오류

일정 모델을 분리한 뒤 새 레이드 추가 창에서 범위 밖의 색상 상수를 참조할 수 있었다. 색상 기본값을 일정 모델에서 명시적으로 내보내고 `App.jsx`에서 가져오도록 수정했다.

### 2. 실시간 갱신이 미저장 수정을 지울 수 있는 문제

다른 브라우저가 공용 DB에 저장하면 현재 브라우저가 편집 중인 멤버, 레이드 또는 일정까지 서버 값으로 교체될 수 있었다. 현재 브라우저에서 수정 중인 항목은 유지하고, 수정하지 않은 항목만 실시간으로 반영하도록 변경했다.

## 자동 검증 결과

- 전체 테스트: 25개 통과
- 프로덕션 빌드: 통과
- Git 변경 형식 검사: 통과
- 미사용 CSS 클래스 검사: 발견 없음
- 남은 빌드 안내: JavaScript 파일 약 680KB 크기 경고. 기능 오류는 아니며 추후 탭 단위 코드 분할로 개선 가능

## 직접 확인할 항목

1. `레이드 관리`에서 `새 레이드 추가` 창이 정상적으로 열리는지 확인한다.
2. 새 레이드를 저장하지 않고 창을 닫았을 때 기존 일정이 바뀌지 않는지 확인한다.
3. 주간 일정에서 캐릭터 하나를 바꾸고 저장 전 하단의 `저장하지 않은 수정 있음` 표시가 유지되는지 확인한다.
4. 가능하면 브라우저 두 개를 열어 한쪽에서 일정 수정 중, 다른 쪽에서 멤버 색상처럼 다른 항목을 저장했을 때 첫 번째 브라우저의 미저장 일정이 유지되는지 확인한다.
5. 캐릭터 전체 갱신 후 기존 주간 일정의 캐릭터 배정이 그대로 남는지 확인한다.
6. 저장 후 새로고침했을 때 일정, 멤버 색상, 레이드 설정이 동일하게 다시 나타나는지 확인한다.
